# 小火花模块版升级与恢复

## 运行环境

核心要求 Node.js 18.17+。Linux / JiuLi 使用隔离契约测试验证；Windows / Miao-Yunzai / TRSS-Yunzai 尚需实际环境验证，不能把路径测试当成整框架实跑。

## 旧版预下载

在机器人根目录执行；先备份 `plugins/xhh-TL/config/config.yaml` 和 `plugins/xhh-TL/data/`，备份放到插件目录以外。命令需使用已经发布模块版的分支。

```sh
git -C plugins/xhh-TL rev-parse HEAD
git clone --depth 1 --single-branch https://github.com/cchanlan/xhh-TL.git temp/xhh-module-upgrade
node temp/xhh-module-upgrade/scripts/prepare-modules.mjs --prepare-for plugins/xhh-TL
git -C plugins/xhh-TL pull --ff-only
```

记下第一条命令输出的旧版提交号。第三条失败就不要执行最后一条；准备成功后再更新、重启。预下载目录必须是新的空目录；迁移完成后可删除 `temp/xhh-module-upgrade`，不要删除正式插件的 `data/module-manager/`。整个过程不复制或上传用户凭据。

旧用户直接更新也支持启动时自动准备；下载失败不会标记迁移完成。锅巴 → 扩展页面 → 小火花模块中心 → 迁移旧版功能 → 重启。

## 主机重启

按自己现有的进程管理方式重启机器人；不要额外裸启动第二个实例。安装、卸载和更新不会自动重启宿主。

## 恢复

1. 保留模块安装记录和用户数据，不删除目录。
2. 若更新事务中断，下次启动先恢复未完成的文件事务。
3. 若需要退回旧版，停止原机器人，在插件目录执行 `git switch --detach <升级前记录的提交号>`，恢复备份的配置后按原方式启动。不要执行 `git clean`。
4. 原有过码服务、第三方插件与外部素材不会被模块卸载删除。

## 开发与发布

业务源码在独立 `xhh-TL-modules` 仓库的 `modules/<id>/files/`；每个文件归属一个包。内部依赖没有业务入口，也不出现在用户选择列表。安装到原来的相对目录，复用既有资源路径与第三方插件导入，不引入另一套平台绝对路径。

在模块仓库执行 `node scripts/build.mjs`，生成带内容标识的不可变包和 `catalog.json`。先发布模块仓库并确认公开下载和 SHA-256，再更新核心的 `config/modules-catalog.json` 并发布核心。已发布包不得覆盖；源码改动会生成新版本。

模块文件不得包含用户配置、CK、Token、运行数据或服务端私库代码；服务端凭据不得写入下载目录。模块管理器不运行安装脚本，只写清单中的普通文件。

## 发布与升级保护

模块版 2.1.0 使用 coreApi=2，模块目录声明最低核心 2.1.0、Node 18.17.0。旧核心会拒绝此目录，请先更新核心再安装或更新模块。缓存目录不兼容时使用内置目录，不能让未来模块版本把管理入口一起拖垮。

安装核心时执行 `pnpm install --dir plugins/xhh-TL`。核心声明模块共用的 JS 依赖，不再依赖宿主恰好安装相同库；sharp 为可选依赖，缺失时普通渲染降级，需要 sharp 的版本资料模块会报告依赖错误。鸣潮读库仍需可用 SQLite 驱动（Node 内置或宿主已安装的兼容驱动）。

升级预下载会检查同名模块文件；与已知旧版原件或将安装内容都不一致时停止，请先备份处理自定义文件，不自动覆盖。原用户配置、记录与额外自备素材不属于卸载目标。

同一用户的单目的地订阅不能被另一个机器人覆盖或取消。需要迁移订阅时，在原机器人处关闭后再到目标机器人开启。取消或重新设置订阅后，尚未发送的旧汇总/推送会再次核对订阅；已发出的官方签到/兑换请求和已经送达的平台消息无法撤销。

模块重载会取消旧 cron job，并阻止旧代回调继续发送。当前任务未退出时新代相同任务不并行执行；重启生效的安装/卸载语义不变。
